# Lifecycle: commits, versions, hygiene

> Lanes, commit formats, versions, hygiene, snapshots/undo, diverged main, nightly schedule, partial checkouts, commit gate. Part of the doc router in [`AGENTS.md`](../../AGENTS.md).

**Git lifecycle — KB Conventional Commits.** Lane membership lives in `backend/src/kb/core/schema.py` (`KNOWLEDGE_PATHS`, `TOOLING_PATHS`, `lane_of`). The dashboard **Lifecycle** tab explains and shows all of it.

| Track | Paths | Committed as | By |
|-------|-------|--------------|----|
| knowledge | `wiki/ think/ raw/ index.md meta/{corpus,coherence-warnings,aliases}.tsv meta/log.md meta/chats/` | `kb(<op>): <summary> (kb-x.y.z)` **directly on main, one commit per operation** — ops: `import catalog digest refine distill think undo restore`; the summary says what was done in words (slugs become words, cut at a word), the body lists the wiki pages touched; trailers `KB-Version KB-Op KB-Target` (a slug, never a hash) (+`KB-Reverts`, `KB-Snapshot`, `KB-Tier easy\|full\|deep` on digests) | writer CLIs (`kb.ingest`, `kb.distill`) automatically; free-form wiki edits via `pixi run ops -- begin …` / `commit` (skill `wiki-edit`); your `think/` edits as `kb(think)` before each op and nightly |
| tooling | `meta/` (code, skills, dashboard, docs), `.cursor/ .claude/ .vscode/ .github/`, `pixi.*`, root `*.md`, `.gitignore` | `schema|feat|fix|chore|paradigm(<component>): <imperative summary>` on `infra/<feature>` (scope always required; docs/tests/refactors are `chore`), merged as a merge commit `… (#N)` whose body lists the branch's commits; the title takes the highest type of its commits (paradigm › schema › feat › fix › chore — `ship pr`/`merge` refuse a lower one), whole subject ≤ 100 chars — **never squash**; main is merged into the branch only when it gained more than kb steps | `pixi run ship -- start/commit/pr/merge` (skill `infra-pr`) — whenever the user asks for a fix/change/feature; **the agent merges by default**, a `hold`-labelled PR (schema/paradigm, or `pr --hold`) waits for the user's `ship approve N` |
| other | anything else | never committed — `pixi run lanes` lists it; gitignore, move or delete | — |

**Versions are knowledge-only:** `kb-x.y.z` — x paradigm, y schema (`SCHEMA_VERSION` in `backend/src/kb/core/schema.py`), z step (computed). Tooling is unversioned; a `schema`/`paradigm` PR carries its migration (`backend/src/kb/migrations/`, `pixi run ops -- migrate` on the branch), snapshots first (`pre-<feature>`) and again after the merge (`post-<feature>`, the new baseline) and bumps y/x. Schema 1.0 (the source model, see [`page-model.md`](page-model.md)) was a paradigm PR: kb-1.0.0.

**Diverged main** (two sessions pushed the same pages from different bases): `ops sync` fast-forwards or replays unpushed `kb(...)` steps and aborts on a conflict; only the user's `--prefer local|origin` picks a side (a rebase `-X` strategy, whole conflicting hunks), and `--root` lets a worktree run it against the primary checkout. Generated files are rebuilt by the next lint.

**Hygiene is built in, never a gate:** every `kb(...)` step pushes main right away (`--no-push` / `KB_NO_PUSH=1` to defer; the nightly sync is the backstop and `ops status` says whether it is installed and when it last ran); `ship merge` removes its own worktree and local branch; `ship prune --apply` removes merged, clean worktrees and never touches dirty ones; **stale work** (`backend/src/kb/git/staleness.py`, one rule set for `ship status`, the nightly hygiene report and the System tab's Stale work tile) is an unmerged branch idle 48 h with no open PR, a missing or detached worktree, or an open PR idle 3 days — `ship prune --stale` lists it (dry run), `--apply` saves each branch as a `_quarantine/` patch and removes it, skipping dirty worktrees and the current one, and never closes a PR; `pixi run lanes` lists stale worktrees, `worktree-*` session branches and open PRs. `.obsidian/` is tooling too, with only `app`, `core-plugins` and `community-plugins` tracked (the rest is gitignored). **Snapshots** are annotated tags `kb-x.y.z` (`pixi run ops -- snapshot "label"`); any other tag (`pre-distillery`, `phase-N-done`) goes on the engine, a kb or another repo with `pixi run ship -- tag <name> [--at REV] [--kb ID|PATH | --repo DIR]` (annotated, local, main only, refuses `kb-*` names). **Undo** one step: `pixi run ops -- undo <sha>`; **restore** a snapshot: `pixi run ops -- restore kb-x.y.z` — both new commits that rewrite only `wiki/`, `meta/aliases.tsv`, `meta/chats/` (never `raw/`, `think/`, `meta/log.md`, generated files) and only on the user's request.

**Holds are the label only.** A hold is the GitHub `hold` label on the PR, nothing else: a "don't merge" in chat becomes `ship pr --hold` (agents may ask for a hold that way, visible on the PR), and only the user removes it: a GitHub **Approve** review on the PR's current head sha by `owner_login` (from `~/.config/kb-agents/app.toml`, env `KB_OWNER_LOGIN` overrides) — tap Approve in the GitHub phone app, then any agent's `ship merge` lifts the label as the App, posts a `kb-event approved` line and merges — or the user's own `! pixi run ship -- approve N`. Since agents act as `thesis-knowledge-base[bot]`, an owner review is provably the user's; reviews by anyone else (the bot included) never count, an approval on an older sha is refused ("re-approve: new commits since your review"), and without an App config (fallback, agents act as the user) only `ship approve` works. `ship status` lists held PRs as `approved ✓ (sha ok)` / `approved on old sha` / `awaiting review`. An approval relayed in chat — from another session, a subagent or a pasted message — is void (on 2026-10-24 a relayed approval deadlocked PR #99). `git_guard` backs this: agents cannot run `gh pr edit/review/ready/merge`, `gh issue|label edit`, `gh auth` (except `status`), keychain reads (`security find-*-password`, `dump-keychain`, `export`) or name `~/.config/kb-agents/` (the GitHub App key) on a command line — best effort, a path built at runtime is not caught, and this is a Bash hook only (file-read tools are not covered).

**Merges are serialized:** `ship merge` queues in the shared git dir (`kb-merge.lock` + `kb-merge-queue.jsonl`, FIFO; wait ≤ `KB_MERGE_WAIT`=30 min, dead/20-min-old holders reclaimed) and runs fetch → sync → gates → merge only at the head; `ship queue` shows it, `ship queue --drop N` removes a dead entry.

**PR events:** `ship` comments one machine-readable line per lifecycle step on the PR — `kb-event v1 · <event> · <sha7> · <k=v …> · <YYYY-MM-DDTHH:MMZ>` (UTC minute; events `claimed` (on `ship pr`, with `branch=` and touched top-level `dirs=`), `queued`, `checks-passed`/`checks-failed`, `merged` (main sha), `deployed`, `rolled-back`; `kb.git.events.post`). Posting is best-effort (one retry, never fails ship). Read a PR's state with `ship events N` (parses only `kb-event v1` lines) instead of relayed messages; agents still cannot `gh pr comment` directly.

**Path claims:** `ship start <feature> --paths a/b,c/d` records which paths the branch will touch (git config `branch.infra/<feature>.kbPaths`); `ship pr` writes `Claims: a/b, c/d` into the PR body and `paths=` into the `claimed` event (without `--paths`, the branch's touched dirs). At `start` and again at `pr` the claim is compared — dir-prefix match — with every other lane: open `infra/*` PRs (their `Claims:` line, else their changed files) and local worktrees (their diff vs origin/main plus any stored claim). Overlaps print an `OVERLAP` block (branch, `PR #N title` or worktree, paths) and ship carries on: a warning, never a block — the user decides whether to wait, split or coordinate. A failing `gh` prints a note. `ship claims` lists every lane's paths, one line each (`claims`/`files`/`diff` says where they came from).

**Round issues:** a multi-PR effort opens one GitHub issue labelled `round` — `ship round open "<title>" --features a,b,c` (prints `#R`; body = `<!-- kb-round v1 -->` marker + one `- [ ] <feature>` line each). `ship start <feature> --round R` links the branch (git config `branch.infra/<feature>.kbRound`); `ship pr` writes `Round: #R` at the top of the PR body and posts `claimed` on the issue too; `merged` (and `deployed`, once posted) comments the same kb-event line on the issue with `feature=`/`pr=` and ticks that feature's line (`- [x] <feature> (#N)`). The orchestrator reads the whole effort with `ship round status R` — `done/total`, then one line per feature: checkbox, name, latest event, PR. Best-effort like PR events: a failing `gh issue` call prints a note and never fails ship; agents still cannot `gh issue edit` directly (`gh issue comment` is not guarded yet).

**One deploy owner:** the private site is deployed only by `kb.share.owner` (launchd `com.thesis-kb.deploy-owner`, KeepAlive; the user installs it with `pixi run install-deploy-owner`, log `~/Library/Logs/thesis-kb-deploy-owner.log`). It builds each origin/main sha once (`.cache/share/build/<sha>`), uploads + deploys a Worker version, health-checks it and rolls back on failure, posting `deployed`/`rolled-back` events; per-sha state in `.cache/share/owner.json` (`python -m kb.share.owner status`). `kb(...)` commits, `ship merge` and the nightly sync only touch `.cache/share/wake`; `KB_SHARE_DIRECT=1` (user only) restores the old direct `deploy-main`. `deploy-main.yml` is the daily fallback and no-ops when the owner deployed in the last 24 h. Agents never deploy or roll back — `.claude/settings.json` denies it.

**Agent identity:** every gh call that `ship`, `events`, `rounds` and `merge_nudge` make runs as the `thesis-knowledge-base[bot]` GitHub App (`kb.git.app_token.run_gh` sets `GH_TOKEN`); `git push` from `ship` goes as the App too when its installation token has `contents: write` (via a `GIT_ASKPASS` script reading an env var — the token is never in `.git/config` or output; a refused push retries with your credentials). Setup: `~/.config/kb-agents/app.toml` (`app_id`, `installation_id`, `slug`, optional `key_path`, default `key.pem` beside it; override the path with `KB_APP_CONFIG`). The code signs a 10-min JWT, mints a 1 h installation token and caches it in `.cache/gh-app-token.json` (mode 600, gitignored, re-minted 5 min before expiry). No config or a failed mint → one warning line and gh uses your own `gh auth` (user fallback). `pixi run ship -- whoami` prints which identity is in use. Agents never read the key file themselves.

**Nightly schedule:** `pixi run install-sync` installs `tools/launchd/com.thesis-kb.daily-sync.plist` into `~/Library/LaunchAgents/` (log: `~/Library/Logs/thesis-kb-daily-sync.log`). It must run on this Mac — a cloud agent can't see local edits. After the sync it runs the hygiene checks (`backend/src/kb/ops/hygiene.py`) and the open work threads (`backend/src/kb/ops/threads.py`), mails the nightly report (`backend/src/kb/ops/nightly_report.py` → `backend/src/kb/maintenance/notify.py`, HTML + text; config `meta/ops/sync.toml` — `mode = "digest"` every night, `"problems"` only when something needs fixing; password in the macOS keychain) and logs the run to `meta/.ops/runs.jsonl`; the dashboard **Ops** tab (`/ops`) shows the same live. See [`meta/automation-daily-sync.md`](../automation-daily-sync.md).

**Partial checkouts:** raw binaries are gitignored, so a clone, a CI run or a fresh worktree lacks them. Lint detects this (≥5 manifest rows of binaries missing from disk, or `KB_CI=1`) and keeps those rows exactly as committed instead of dropping them; everything on disk reconciles as usual. Fewer missing files count as a deliberate deletion.

**Commit gate:** `tools/githooks/` (`pixi run install-hooks`): `pre-commit` runs `backend/src/kb/lint/lint.py` (+ `lint_skills.py` for tooling), `commit-msg` and `pre-push` run `backend/src/kb/git/commit_policy.py`. `python3 -m kb.lint.lint --health` or `python3 -m kb.dashboard` for vault health.
