Every subject has a scope. Knowledge summaries are noun phrases (the op is the verb); infra summaries start with an imperative verb. Infra types by what changed: schema (note rules) › feat (new capability) › fix (wrong behaviour) › chore (no behaviour change — config, docs, tests, refactors); a PR merge takes the highest type of its commits. Components: vault raw books think ingest lint guard dashboard skills distill query export scrap git obsidian claude gemini. Ops: import catalog digest refine distill think undo restore. Trailers: KB-Version, KB-Op, KB-Target, KB-Reverts, KB-Snapshot.

Knowledge work

pixi run ops -- log → pixi run ops -- undo <sha> (skill kb-undo). Only wiki/ is rewritten.

query-knowledge — read-only; filing an answer back is a refine session.

Guardrails

  • Agents never run git writes. The shell hook allows only single pixi run ops|ship|daily-sync invocations; chained commands are refused.
  • Wiki edits need an open operation (src/kb_distillery/git/guard.py; warns now, blocks once strict).
  • Commit messages are checked by scripts/githooks/commit-msg; pushes to main must be kb steps (z+1) or PR merges (pre-push).
  • Undo and restore never touch raw/, think/, meta/log.md or generated files, and never reset history.
  • PRs are never squashed; schema PRs snapshot before (pre-) and after (post-) the merge. The nightly sync takes the same lock as ops.
  • Hygiene is automatic, never a gate: every kb step pushes main right away (the nightly sync is the backstop); ship merge removes its own worktree; ship prune --apply removes merged, clean worktrees only; stale worktrees, session branches and the nightly state show up here and in pixi run lanes.
