Start here

How to add and edit knowledge, and how to build a new feature for the knowledge base. You talk to the agent (Claude Code or Cursor); the trigger phrases below pick the right skill, and every change lands as one reviewable git commit.

Three places, three owners

raw/ — inputs

PDFs, slides, mail, chat exports. Yours and immutable: only the scrap/catalog CLIs add files; agents never edit them.

wiki/ — knowledge

The notes in three layers: sources (papers, lectures, articles…), collections (books, courses, series) and concepts (ideas, topics, questions, people). Written by agents through skills; every change is a kb(op) commit you can undo.

think/ — your thinking

Schema-free drafts that only you edit. Committed for you as kb(think); promoted into the wiki with distill-think.

Say the phrase to the agent. The skill runs the CLI, which commits the result on main as kb(<op>): … (kb-x.y.z) — one commit per operation.

Develop a feature

Tooling — dashboard, explorer, ingest CLI, skills, schema — never commits to main. It goes through a branch and a pull request you approve. Skill: infra-pr. Just say what you want — fix the graph legend, add a filter to Digestion — and the agent runs the steps below and gives you the PR link; say merge when you are happy. (The full phrase → skill table is the Intent router in AGENTS.md.)

  1. Branch. pixi run ship -- start <feature> --worktree — an isolated copy on infra/<feature>, so your vault and the nightly sync stay on main.
  2. Build and try it. Edit code in the worktree. Try the dashboard from there with pixi run dashboard -- --port 8799 (your usual one stays on 8765).
  3. Commit. pixi run ship -- commit "feat(dashboard): add …" — runs tests, lint-skills and lint first; commits tooling files only.
  4. Open the PR. pixi run ship -- pr --title "feat(dashboard): add …" — pushes and gives you the GitHub link to review.
  5. Merge. Approve, then say merge → pixi run ship -- merge makes a real merge commit … (#N) (never squash) and updates your checkout.

A new skill

Say create skill <name> (skill create-skill) → pixi run lint-skills → same PR flow, as feat(skills): …. A skill that writes knowledge must end in an op commit.

A schema change

New note type, frontmatter field or rule that lint enforces: bump SCHEMA_VERSION in src/kb_distillery/core/schema.py, add src/kb_distillery/migrations/NNNN_<name>.py, run pixi run ops -- migrate on the branch, commit as schema(<component>): …. Merging snapshots first and bumps the middle digit.

A new kind of source

Handler sub-skills (scrap-data/<type>, ingest-to-catalog/<type>) as feat(scrap)/feat(ingest), plus naming and tags as schema(raw) — one PR. Then ingest the items as normal knowledge steps.

Scope is always a component: vault raw books think ingest lint guard dashboard skills distill query export scrap git obsidian claude gemini. Infra summaries start with a verb. Versions are knowledge-only: kb-x.y.z = paradigm · schema · step.

Daily rhythm

  • Morning: pixi run launch opens this dashboard. Digestion shows the inbox and backlog.
  • During the day: ask for skills; each finished operation is already committed.
  • 22:00: the nightly sync commits your think/ edits, anything left over, and pushes main with its snapshot tags.
  • Weekly: snapshot "week NN" to name a state you might share or return to.

Rules that protect you

  • Agents never run git writes; only the ops, ship and daily-sync tools commit.
  • raw/ and think/ are never edited by agents, never rewritten by undo or restore.
  • Undo and restore add commits — history is never rewritten.
  • Tooling changes need your PR approval; PRs are never squashed.
